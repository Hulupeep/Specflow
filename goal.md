# Specflow goal

Enable unassisted development within explicit standing authority: Colm supplies
general intent; agents research, select, specify, build and evaluate safe, useful
features, then explain the evidence and use it to improve the next choice.
Reduce time to validated value and revenue without making Colm the routine
decision maker or counting agent activity as product progress.

When a research agent has already selected an opportunity and opened issues,
Specflow begins there: strengthen the issues proportionately, build, verify and
return evidence. Do not repeat discovery or replace the researcher's choice
without a concrete contradiction, safety conflict or failed feasibility check.

HeyStax is the intended operational control plane where people and agents set
intent, exchange scoped work, inspect results and instruct the next cycle. The
existing Improve engine owns execution and authoritative run evidence. See
[docs/design/intent-to-evidence.md](docs/design/intent-to-evidence.md) for the
delivery target and current capability gaps.

Roles are portable across agents and providers. The Chief of Staff Stax holds
the standing role brief; project/task state and evidence must survive changing
the role holder. A particular bot, chat session or notification transport is not
the source of authority or the only place operational knowledge is stored.

Specflow is a trust harness for coding agents: turn a user's intent into work
whose acceptance is established by contracts, executable evidence and independent
review. The product mission and supported workflow are described in
[docs/PRD.md](docs/PRD.md); repository instructions and existing YAML contracts
remain authoritative.

The interactive builder owns the conversation. Duo checks meaningful work batches
with the other native CLI, retains findings and evidence, and continues toward the
same scoped acceptance. A model's confidence or a green process exit alone cannot
establish completion, deployment or customer validation.

TypeSafe supplies bounded semantic judgments. Its advisory and opt-in routing
studies preserve the approved builder, peer review and release gates. Routing
benefit and effective provider settings remain unproven wherever independent
labels, actual execution or native metadata are missing. The bounded study and
its outstanding real-run reports are tracked in GitHub issue #160.
