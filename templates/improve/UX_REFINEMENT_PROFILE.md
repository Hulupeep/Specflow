# Restrained product and UX refinement profile (#175)

Used by the scout, the UX critic before a contract is frozen, and the
independent UX evaluator afterwards. It is a rubric for judgment (evidence
levels 3–4). It never replaces a level 1–2 check the contract requires.

## Posture

| Prefer | Over |
|---|---|
| refinement | redesign |
| removal | unnecessary addition |
| workflow | decoration |
| clarity | novelty |
| good defaults | extra settings |
| less cognitive work | more UI |

Preserve established navigation, visual language and behaviour unless the
recorded evidence shows they cause the problem.

## Inspect the affected journey for

- user intent: what is the person trying to finish on this screen?
- unnecessary clicks, navigation, decisions, fields or repeated input
- information shown at the wrong time, repeated, or missing when needed
- ambiguous labels, buried actions, weak hierarchy, unclear state
- dead ends and poor recovery; empty, loading, error and success states
- mobile/touch and responsive behaviour (overlap, overflow, truncation)
- accessibility: names, focus order, contrast, target size

## A valid candidate states

1. an observation (what was seen, where, with evidence);
2. the user consequence (time, clicks, errors, lost context, unreadable state);
3. how that consequence can be measured or observed before and after.

"Modernize", "cleaner", "refresh", aesthetic preference or generic redesign is
not a user problem. A redesign may be recorded as an opportunity; it is not
selected for an unattended cycle.

## Evaluator questions

- Does the change solve the observed problem on the affected journey?
- Did it add interface where removal or reordering would do?
- Is anything that used to be visible, reachable or understandable now worse?
- Does it hold on the mobile viewport and with keyboard/screen reader names?
- Is the claim limited to what the runtime evidence shows?
